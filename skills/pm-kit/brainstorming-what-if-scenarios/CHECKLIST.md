# What If Scenarios Analysis — Acceptance Checklist

- [ ] The focal question is stated in a single, specific sentence that identifies what the scenarios are meant to inform.
- [ ] At least three key planning assumptions are recorded, each stated as a belief the current plan rests on.
- [ ] At least one trigger event is identified for each key assumption.
- [ ] At least two full scenarios are constructed, each including: trigger, project impact, early warning signals, and contingency response.
- [ ] Each scenario's contingency response is classified as requiring advance action or reactive action.
- [ ] At least one compound scenario (two triggers firing simultaneously) is considered and recorded or explicitly noted as not applicable.
- [ ] Advance-action contingencies have owners, target dates, and first actions recorded in the action plan.
- [ ] The output cites the canonical reference URL (`https://en.wikipedia.org/wiki/Scenario_planning`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and does not include fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/brainstorming-what-if-scenarios/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.

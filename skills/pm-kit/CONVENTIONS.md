# Skill Authoring Conventions

These are the locked conventions every skill in `agentic-pm-kit/skills/pm-kit/` must follow. Established at convention gate G1 by the `brainstorming-five-whys` reference skill. Any skill author touching this directory must read this file and the gold-standard skill at `brainstorming-five-whys/` before writing.

If a convention here conflicts with the design spec at `docs/superpowers/specs/2026-04-20-agentic-pm-kit-design.md`, the spec wins — surface the conflict to the orchestrator before authoring.

---

## File layout per skill

Every skill is a directory under `skills/pm-kit/<skill-name>/` containing exactly:

```
<skill-name>/
├── SKILL.md       (the skill itself — frontmatter + Markdown body)
├── TEMPLATE.md    (the artifact scaffold the agent fills in)
└── CHECKLIST.md   (the binary acceptance gate)
```

`<skill-name>` is kebab-case ASCII. It MUST match the YAML `name` field in `SKILL.md` — this is required by the agentskills.io portable spec.

`EXAMPLE.md` is added later by Team D after the worked-example run. Skill authors do NOT create it.

## SKILL.md structure

### Frontmatter (portable baseline only for v1)

```yaml
---
name: <skill-name>
description: "..."
---
```

- `name` — kebab-case, identical to the parent directory name.
- `description` — one or two sentences, ends with a clear `"Invoke when..."` trigger so the host CLI's skill router selects it correctly.
- **Do not add Claude-specific frontmatter fields** (`allowed-tools`, `model`, `context`, etc.) in v1. The same SKILL.md must load unmodified into both Claude Code and Gemini CLI per spec §7.3.

### Body — five sections in this fixed order

```markdown
> Adapted from bmad-method:<source-skill> (MIT, © 2025 BMad Code, LLC). See THIRD_PARTY_NOTICES.md.
   ↑ for [BMad-vendored] skills only

> Originally authored for Agentic PM Kit (MIT).
   ↑ for [Extension] skills only

## When to use
## Summon the SME
## Facilitation script
## Languages
## Acceptance gate
```

The attribution blockquote appears immediately after the frontmatter (no other content between them). Choose the correct variant per the skill's classification in design spec §5.

Section order is locked. Section content is skill-specific but must follow the patterns below.

### "When to use" — required content

A short paragraph and a bulleted list of triggers. PM-framed (sprint impediments, stakeholder signals, milestone events) — not generic. Close with a "do not invoke for…" line that disambiguates against neighboring skills. ~5–10 lines.

### "Summon the SME" — required content (offline-first)

Reads `.pm-kit.config.json` → `sourcesMode`. Two branches in this order:

1. **Online (opt-in).** "fetch the URL stored at the key `sources.<skillKey>` in `vendor/pm-kit/sources-index.json` using your available web-fetch capability. Do not name a specific tool — use whatever your runtime provides." This phrasing is locked for cross-CLI portability — do not say `WebFetch`, `web_fetch`, `BrowserTool`, or any tool-specific name.
2. **Offline (default).** "rely on your general knowledge of <topic> as described by <canonical authority>. Cite the canonical URL from `vendor/pm-kit/sources-index.json` at key `sources.<skillKey>` in the output. Do not fabricate quotations or page numbers."

Always end with a sentence stating the canonical URL verbatim, e.g., "In both cases, the URL to cite is `<URL>`."

The `sources.<skillKey>` is a JSON path — it's the contract with `vendor/pm-kit/sources-index.json`. Coordinate with the A6 author so the key exists.

### "Facilitation script" — required content

Numbered steps the agent walks the user through. Last step is always the save-to-disk terminal step:

> **Step N — Save the artifact.** Save the filled artifact to `docs/pm-kit/outputs/<skill-name>/<short-slug>.md`. `<short-slug>` is a kebab-case ASCII slug (max 40 chars) derived from a salient field of the input. Confirm the final path with the user before writing. If the file exists, ask: overwrite, append a date suffix (e.g., `-2026-04-20`), or pick a new slug. The artifact begins with the three-line provenance header below (HTML comments, do not render):
>
> ```
> <!-- Generated by agentic-pm-kit:<skill-name> on YYYY-MM-DD -->
> <!-- Languages: communication=<value>, output=<value> -->
> <!-- Source mode: offline | online -->
> ```

Only the skill name in the first comment changes per skill.

### "Languages" — required content (locked text shape)

Bifurcates dialogue language from artifact language. Both fields are free-form strings, read verbatim, no hardcoded list:

- **Facilitation dialogue.** Uses `language.communication` from `.pm-kit.config.json`.
- **Filled artifact (saved TEMPLATE.md output).** Uses `language.output`. Falls back to `language.communication` if `output` is absent or empty.

Include the example-values line: `"en-US"`, `"es-MX"`, `"Português brasileiro"`, `"Mandarin Chinese"`, etc.

### "Acceptance gate" — required content

One short paragraph pointing to `CHECKLIST.md` (sibling file) and reminding the user to mark **PASS** or **FAIL**. On **FAIL**, the user returns with notes.

## TEMPLATE.md structure

- Begins with the three-line HTML-comment provenance header (with `<value>` / `YYYY-MM-DD` / `offline | online` placeholders the agent fills at save time).
- Then `# <Artifact Title>` H1.
- Then `## <Section>` H2s for major sections, `### <Sub>` H3s for sub-items.
- Use horizontal rules (`---`) between major sections for visual scanability.
- Slot placeholders use italic underscores: `_[Description of what goes here]_`.
- Every template ends with a `## Source consulted` section recording the canonical reference URL, the source mode used, and a note about whether the page was fetched (online) or general knowledge was used (offline).

---

## CHECKLIST.md structure

- Title: `# <Artifact Name> — Acceptance Checklist`
- 7–12 items as GFM task-list checkboxes (`- [ ]`).
- Each item is a declarative statement (the artifact is the implicit subject), phrased so the answer is yes/no.
- Two items are mandatory across all skills:
  - The facilitation dialogue is in `language.communication` and the saved artifact is in `language.output` (with the fallback rule).
  - The artifact is saved to `docs/pm-kit/outputs/<skill-name>/<slug>.md` and begins with the three-line provenance header.
- Trailing line, verbatim, no variation:

```
> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.
```

If a skill needs more than 12 items, group with `## Subsection` H2s (e.g., Content / Format / Compliance).

## Tone

PMP-textbook neutral. Second-person imperative ("Ask the user…", "Confirm the…"). No hedging ("let's", "feel free to", "you might want to"). No jokes. The skill body is read by both the agent and human reviewers; one consistent voice across 38+ skills makes the kit feel deliberate rather than crowdsourced.

---

## Trademark and attribution

- The literal string `"BMad"` and any case variant MUST NOT appear in: skill names, frontmatter, body prose, template content, or checklist content. The ONLY permitted occurrence is the attribution blockquote, where `bmad-method:<source-skill>` is a code-style identifier referencing the upstream source repo (permitted under BMad TRADEMARK.md "compatibility reference" clause).
- `THIRD_PARTY_NOTICES.md` at the repo root is the canonical attribution location. Per-skill attribution is the one-line blockquote.
- The `[Extension]` attribution blockquote (`> Originally authored for Agentic PM Kit (MIT).`) does NOT mention BMad at all.

---

## Forbidden content

- No MCP references. Anywhere.
- No tool-specific names (`WebFetch`, `Bash`, `Read`, `Write`, `BrowserTool`, etc.) in user-facing skill body — refer to capabilities, not tools.
- No hardcoded language lists.
- No fabricated quotations, page numbers, or invented PMBOK structural details when in offline mode.
- No "BMad" outside the attribution blockquote.

---

## Length budget

| File | Target | Hard ceiling |
|---|---|---|
| SKILL.md (body, excl. frontmatter) | 60–120 lines | 200 lines |
| TEMPLATE.md | 40–120 lines | 250 lines |
| CHECKLIST.md | 7–12 items + title + trailing line | 15 items |

Skills that exceed the hard ceiling get bounced back. Concise skills load faster and cost less per invocation.

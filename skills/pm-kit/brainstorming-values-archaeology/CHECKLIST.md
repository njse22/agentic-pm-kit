# Values Archaeology — Acceptance Checklist

- [ ] The anchoring decision or conflict is named as a specific, concrete situation — not a general theme.
- [ ] Observable artifacts are listed as actual behaviors, decisions, or patterns — not opinions or interpretations.
- [ ] Espoused values are recorded verbatim or with a clear source citation; no values are inferred or invented.
- [ ] At least one basic assumption per espoused value is derived from an observed trade-off outcome, not from speculation.
- [ ] The gap map explicitly names at least one divergence between an espoused value and a basic assumption.
- [ ] Implications for the project include at least one decision to re-examine and at least one named risk.
- [ ] The output cites the canonical organizational-culture reference URL (`https://en.wikipedia.org/wiki/Edgar_Schein`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and does not include fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/brainstorming-values-archaeology/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.

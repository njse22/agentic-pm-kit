# Reverse Brainstorming Analysis — Acceptance Checklist

- [ ] The goal statement is stated in a single, clear, positive sentence — it is the outcome being protected, not the problem to be solved.
- [ ] The inverted question is an explicit restatement of the goal as its opposite, presented to the team before idea generation begins.
- [ ] At least ten failure modes are generated in response to the inverted question; implausible items are not filtered at this stage.
- [ ] Each failure mode has a corresponding inverted solution or risk control recorded in the artifact.
- [ ] Each inverted solution is classified as: already in the plan, a known risk, or new.
- [ ] All "new" items are surfaced separately and prioritized by likelihood and impact.
- [ ] The action plan addresses at least the top two new items, each assigned to a role or team with a target date or sprint.
- [ ] Each action specifies a concrete first step (e.g., add to risk register, add to sprint backlog, update a plan section).
- [ ] The output cites the canonical reference URL (`https://en.wikipedia.org/wiki/Reverse_brainstorming`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and does not include fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/brainstorming-reverse-brainstorming/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.

# Story Execution — Acceptance Checklist

- [ ] The story summary includes a story ID, title, user-story sentence ("As a / I want / So that"), and a complete list of acceptance criteria.
- [ ] All acceptance criteria are phrased as measurable, verifiable outcomes (not vague intent statements).
- [ ] The implementation plan maps every technical step to at least one acceptance criterion.
- [ ] At least one test is recorded per acceptance criterion, with a type and status noted.
- [ ] Review notes identify the reviewer, date, any issues flagged, and the resolution or deferral of each issue.
- [ ] Every Definition of Done item is listed and its status (met or unmet) is recorded.
- [ ] If any DoD item is not met, a plan to resolve it before story closure is stated.
- [ ] At least one lesson learned is recorded.
- [ ] The output cites the canonical user-story reference URL (`https://en.wikipedia.org/wiki/User_story`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and does not include fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/story-execution/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.

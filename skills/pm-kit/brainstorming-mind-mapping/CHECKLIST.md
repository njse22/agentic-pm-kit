# Mind Map — Acceptance Checklist

- [ ] The central concept is named and is a specific topic, problem, or decision — not a vague theme.
- [ ] At least 4 first-level branches are present, each represented by a distinct category or dimension.
- [ ] Each branch has at least 2 second-level sub-items populated; no branch section is empty or contains only placeholder text.
- [ ] Third-level detail is present on any branch where the team identified additional granularity during the session.
- [ ] At least one cross-link between nodes on different branches is documented, or the absence of cross-links is explicitly noted.
- [ ] The high-priority table identifies 3–5 nodes with a stated reason for each.
- [ ] The output cites the canonical Mind Mapping reference URL (`https://tonybuzan.com/`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and does not include fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/brainstorming-mind-mapping/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.

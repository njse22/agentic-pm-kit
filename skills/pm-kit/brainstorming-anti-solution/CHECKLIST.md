# Anti-Solution — Acceptance Checklist

- [ ] The goal statement is a single sentence describing a real, current project objective.
- [ ] The inverted goal explicitly reframes the objective as a failure target before anti-solutions are generated.
- [ ] At least ten anti-solutions are recorded before any evaluation begins.
- [ ] Anti-solutions span at least three of the five prompt categories (Communication, Planning, Stakeholder management, Quality, Process).
- [ ] Each anti-solution has a corresponding positive inverse that is logically derived, not merely the word "not" prepended.
- [ ] The novel findings section contains only positive inverses that are absent from the current project plan.
- [ ] At least three novel findings are prioritized and assigned to a named owner with a target date or sprint.
- [ ] The output cites the canonical inversion-thinking reference URL (`https://fs.blog/inversion/`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and does not include fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/brainstorming-anti-solution/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.
